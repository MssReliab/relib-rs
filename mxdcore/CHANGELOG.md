## Unreleased

- **New crate.** Matrix Decision Diagrams (MxD): relations over multi-valued state vectors, and the sets they act on, in one forest. Intended for the multi-state boundary operator `B = R ∩ (L × U)`, which does not require the structure function to be monotone.
- **`MxdManager`** — arena, hash-consing and mark-and-sweep `gc` in the style of `relib-mdd`'s `MddManager`. Two terminals only (`Zero`, `One`); the `Undet` of the MDD forest exists there for partial structure functions and has no meaning for a set or a relation. `defvar` declares a variable once and creates both a set header (`edge_num = n`) and a relation header (`edge_num = n²`) at that level, under distinct `HeaderId`s so the unique table cannot confuse the two.
- **Representation: fused relation nodes.** A variable occupies one level, not MEDDLY's interleaved unprimed/primed pair; a relation node carries an `n × n` block with child `a * n + b` denoting the transition `(from = a, to = b)`. This gives up sharing of target sub-graphs across source values in exchange for a diagonal that is local to one node, which makes identity reduction a predicate rather than a parent-side rewrite. **Node counts are consequently not comparable with MEDDLY's.**
- **`create_set_node`** is fully reduced (skipped level = don't-care, same rule as `MddManager::create_node`); **`create_rel_node`** is **identity reduced** — a block that is `c` down the diagonal and empty off it says the component does not move, so the level carries nothing of its own and is elided. The fully-reduced rule (*all entries equal*) must never be applied to a relation: eliding a relation level means `to == from`, while "all entries equal" means `to` is anything, and confusing them is the difference between the identity and `Ω × Ω`. Because source and target share a node here, the diagonal test is local; under MEDDLY's interleaved layout it cannot be, which is the main reason for the fused representation.
- **`enumerate_set` / `enumerate_relation` / `cardinality_set` / `cardinality_relation`** — the ground truth later operations are checked against. Documents and implements the two *opposite* skip rules: a skipped set level is a don't-care, a skipped relation level is the identity. The relation rule is already in place though unreachable today, so enabling identity reduction changes one reduction rule and not the semantics.
- **`Src` / `Dst` minterm patterns** replace MEDDLY's raw `-1`/`-2` sentinels. An invariant component is `(Src::Any, Dst::Same)`; the silently-wrong alternative (MEDDLY's `DONT_CARE` on the primed side, which means "any target state" rather than "does not move") must be requested by name as `Dst::Any`. `from_meddly_sentinels` replays raw MEDDLY vectors for cross-checking.

- **Boolean operations** (`mxd_ops`), named per kind because `Zero` and `One` are shared between sets and relations, so a node alone does not say how it should be read: `and_set`/`or_set`/`not_set`/`setdiff_set` and `and_rel`/`or_rel`/`not_rel`/`setdiff_rel`.
- Set operations are the ordinary MDD apply from `mddcore::mdd_ops` and share one op-keyed compute table. Relation operations **carry an explicit level**: a skipped relation level means the identity, so the same pair of operands combines differently depending on how many levels remain, and the level has to be part of the cache key. That leaves no room for an op code in the three available key words, so each relation operation gets its own table, keyed `(f, g, level)`. Those tables are cleared rather than filtered by `gc`, since `retain_live3` would test the level word as a node id.
- A skipped relation level is expanded into the explicit diagonal block it stands for, which makes one elementwise pass correct for intersection, union *and* complement. Complementing cannot bottom out at `One` — that denotes the identity, not `Ω × Ω` — so the empty relation complements to a lazily built spine of full blocks (`full_relation`).

- **`cross`** — the cartesian product `{ (m, m') : m ∈ f, m' ∈ g }`, taking two *set* edges to a *relation* edge, with `|cross(a, b)| = |a| · |b|`. Not commutative, so unlike `and_rel`/`or_rel` there is no operand swap to canonicalise the cache key. Both operands being sets, a skipped level is an independent don't-care on each side and their product is the full `n × n` block — not the identity, which is why the level cannot be recovered from the operands.
- **`transpose`** — the converse relation, mirroring each block about its diagonal. A skipped level (the identity) is its own transpose.
- **`boundary(lower, upper, rel)`** — `B = R ∩ (L × U)`. Monotonicity of the underlying structure function is nowhere assumed, which is the point: repair and restart are analysed the same way as failure.

- **`post_image` / `pre_image`** — the forward and backward images, `{ m' : ∃ m ∈ S, (m, m') ∈ R }` and `{ m : ∃ m' ∈ S, (m, m') ∈ R }`. Each quantifies away one side of the transition and indexes the result by the other; they satisfy `post(S, transpose(R)) == pre(S, R)`.
- Identity reduction makes an invariant component free: a transition where one component moves and `k-1` do not costs **one node whatever `k` is**, instead of `k`. That is the shape the repair/restart workload is built from, so the reduction is what makes it tractable rather than an optimisation.

- **Graphviz output** (`mxd_dot`, `Dot` impl). Set nodes are circles, relation nodes double circles labelled `x'`, terminals squares. Relation edges are labelled `a→b` — the transition the block cell stands for — rather than a flat child index, and edges into `Zero` are **not** drawn: a relation node has `n²` of them and is usually sparse. Set nodes keep every edge, matching the `mddcore` renderers. Note that an elided level is invisible, and for a relation that means the component *does not move*: a `T` reached from a relation node is the identity below it, not `Ω × Ω`.
- `gc` also clears the memoized full relations, whose entries are node ids and would otherwise name reclaimed slots.

- **Cross-checked against MEDDLY.** `tests/fixtures/meddly_cases.txt`, generated by `tools/gen_meddly_fixture.jl` through Meddly.jl, records 25 randomised cases as raw MEDDLY sentinel vectors together with the cardinality and full membership of `rel`, `cross`, `boundary`, and the four images. The fixture is committed, so the check runs without a Julia or MEDDLY toolchain. **Cardinality and membership only** — node counts cannot agree, since this crate fuses each variable's source and target into one node where MEDDLY interleaves two levels, so comparing them would mean nothing. The generator decides membership by intersecting with an explicit singleton and reading the cardinality, rather than by walking the diagram: walking it would re-derive MEDDLY's layout and identity reduction inside the generator, the very semantics under test, and a mistake there could agree with a mistake in this crate's enumerator and hide both.
- The randomised oracle suites also run across varying shapes — one to four variables, domains from one to four states — rather than only the fixed three-variable case. A single-state component is the one place the identity and the full relation genuinely coincide, so identity reduction collapsing a full block there is correct rather than the confusion the rule is most exposed to; that case is pinned per shape.

- **Cardinalities are `u128`, not `u64`.** A relation lives in `Ω × Ω`, and the multi-state case studies reach `|Ω| = 3^22 ≈ 3.1e10`, so `|Ω|²` overflows 64 bits by a wide margin on exactly the systems this crate exists for. MEDDLY returns a `double` here and goes approximate at that size; these counts stay exact.

- **`node_count(root)`** — the size of one diagram, as opposed to `live_node_count`, which is the size of the whole arena.
- **`examples/boundary_nonmonotone.rs`** — the boundary operator on `distribution_system(n)` (Sedlacek et al. 2021, RESS 215:107824 §4.2), a genuinely non-monotone multi-state system where producing more can lower φ, so minimal path/cut vectors do not apply. Mirrors `MDDMinsol/scripts/boundary_nonmonotone.jl`. φ depends only on the component sum, so the level sets are built directly as boolean MDDs and no value-carrying diagram is needed.
- **Agrees with MEDDLY on all 42 `(n, j)` rows** of that case study, `n = 2..22` — see `results/README.md`. `test_distribution_system.rs` pins the small end plus the closed form `|B_1| = n²`, and checks the system really is non-monotone rather than taking it on trust.

- **`examples/repair_restart.rs`** — boundary transitions under repair and restart on the same non-monotone system, over four relations (`dec`, `inc`, `restart`, `dec ∪ restart`) and both crossing directions per level. This is the case minimal path/cut vectors cannot express at all, so none of these numbers has an alternative derivation. **All 104 `(n, relation, level)` rows agree with MEDDLY** over `n = 2..14`; `tests/test_repair_restart.rs` pins 32 of them plus the structural facts — degrading enters the productive band while repairing leaves it, the two being converses under `transpose`, and restart overshooting harder than gradual repair. See `results/README.md`.
- `MDDMinsol` exported `repair_relation` but had neither a script nor a test for it, so the MEDDLY reference (`tools/gen_repair_reference.jl`, `results/repair_restart_meddly.csv`) was generated for this comparison rather than taken from the research repository.

- **New `analysis` module — the layer most callers should use.** `System` (components and their states), `Levels` (the level sets of a structure function), `StateSet` and `Transitions`, and the boundary operator in that vocabulary. A case study is now a few dozen lines rather than two hundred, and the `phi` / `level_set` / `relation` helpers that had been copied into five files are gone.
- Sets and relations are **distinct types** here. The engine represents both as plain node ids with shared `Zero`/`One` terminals, so there a node alone does not say which it is — and `One` read as a relation is the *identity*, not everything. `StateSet` and `Transitions` cannot be confused, and each carries the `System` that produced it, so mixing two systems panics in debug builds instead of quietly computing on the wrong forest.
- Two ways to give φ, with their costs stated: `levels_from_states` takes a plain function of the state vector and evaluates it everywhere (simple, exponential, right while a system is small); `levels_from_fold` threads an accumulator down the components and is linear in the diagram, provided the accumulator is kept bounded.
- Relation vocabulary: `degrade`, `repair`, `restart`, `fail`, `single`, `stay`, plus union / intersection / difference / `converse`, the boundary operator (`boundary`, `boundary_up`, `boundary_down`), the existential projections `sources` / `targets`, and `step_forward` / `step_backward`.
- The examples and tests were rewritten onto it and **reproduce the committed results byte for byte**, except `boundary_nonmonotone_rust.csv`'s `live_nodes` column — that is the size of the whole arena, intermediates included, so it moved by about `n` when the example started building `degrade` and `repair` separately before uniting them. No cardinality or per-diagram node count changed.

- **The `analysis` handles now follow the workspace's convention.** `StateSet` and `Transitions` hold `Rc`/`Weak` back-references to the forest, exactly as `relib-bss`'s `BddNode` and `relib-mss`'s `MddNode` do, and the operations moved from `System` onto the handles (`rel.boundary_up(&levels, j)`, `set.count()`) so `System` builds and handles operate — the same division as those crates.
- Two consequences. **A handle is a garbage-collection root while it is alive**, so `System::gc` exists and collecting can never invalidate something still held; the previous design had bare node ids, could offer no `gc` at all, and its arena only ever grew. And the cross-forest check is now `Weak::ptr_eq` on a back-reference the handle already carries, rather than a separate system tag — the same guard `relib-bss` and `relib-mss` gained in the same round.
- Handles are `Clone` rather than `Copy` now, since cloning takes another reference to the root. The rewritten examples reproduce the committed results **byte for byte**, `live_nodes` included.

### Performance

Three changes, in the order a measurement found them. Every result is unchanged — the committed CSVs are byte-identical apart from timings and the `live_nodes` column — and `examples/bench_boundary.rs` is the harness.

- **The boundary no longer materialises the product.** `R ∩ (L × U)` was `and_rel(cross(L, U), R)`, and the product is dense where the intersection is sparse: at 60 components of five states `cross` alone was **451 ms of a 454 ms** boundary, building 23 072 nodes for a result of 2 763. A three-way recursion over `L`, `U` and `R` together skips a cell unless the relation admits that transition *and* the source is in `L` *and* the target is in `U`, which for a relation where one component moves at a time removes nearly all of them. **~50–68× on that case**, 1.2–3.4× on the others. Its memo is a `BddHashMap`, not the shared `ComputeCache`, because the key is `(lower, upper, rel, level)` — four words where that table holds three.
- **Relation families are built directly instead of by repeated union.** `degrade`, `repair`, `restart` and `fail` were `k · (states−1)` singletons unioned one at a time, each union costing `O(k · n²)`: 13.9 ms to produce a hundred nodes at 100 components of five states. The structure is a chain — at each component, either it takes an admitted step and everything below is the identity, or it holds and something below stepped — so the whole relation is `k` node creations and no apply at all. **~480× (13.9 ms → 29 µs)**, and the arena shrinks 3.5–6.4× because none of the intermediates are created. Verified by constructing both ways and asserting the *same node*, which hash-consing makes exact.
- **The hot recursions read operand cells one at a time** rather than collecting three child vectors per call. Each recursive step needs `&mut self`, so no borrow survives it and the collections bought nothing. Applied to `boundary`, `post_image` and `pre_image`: **1.2–1.5×**.

**`publish = false`.** The crate is in the workspace and covered by `cargo test`, but is deliberately kept off crates.io while the API is still moving — a published version can never be re-uploaded. Removing that line brings it into the lockstep release, published after `relib-common`, its only dependency.
